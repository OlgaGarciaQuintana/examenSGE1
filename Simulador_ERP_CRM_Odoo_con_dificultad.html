Tema 1 · Identificación de ERP, CRM y BI

Qué son, cómo se despliegan y cómo se aprovechan los datos de la empresa.

Ver apuntes
  • ERP: integra áreas como compras, ventas, almacén, producción y contabilidad. CRM: relación con clientes, ventas y marketing. BI: análisis para decidir.
  • Licencias: software libre no implica gratis. GPL incorpora copyleft; las licencias permisivas ofrecen más flexibilidad para derivados.
  • Despliegues: on-premise en instalaciones propias; IaaS = infraestructura; PaaS = plataforma; SaaS = aplicación como servicio.
  • Arquitectura: presentación, lógica de negocio y datos. Un ERP usa módulos y comparte información entre circuitos.
  • Operativa: la recepción actualiza existencias; las proformas no son facturas contables; fabricación emplea listas de materiales.
  • BI: OLTP registra transacciones, ETL transforma datos, data warehouse los integra, data marts los organizan por áreas y OLAP los analiza.

Tema 2 · Implantación técnica de Odoo

Servidor, configuración, bases de datos, usuarios y funcionalidades.

Ver apuntes
  • Odoo: sistema ERP-CRM modular. El material diferencia Community y Enterprise y estudia Odoo 13.
  • Arquitectura: PostgreSQL almacena datos; el servidor Odoo contiene la lógica; el cliente se conecta desde el navegador.
  • Instalación: All-In-One en Windows para pruebas; Linux para entornos dedicados; Docker para desarrollo y pruebas. Ejemplos con puertos 8069 (Odoo) y 5432 (PostgreSQL).
  • Configuración: odoo.conf incluye rutas y conexión; odoo.log contiene eventos. La contraseña maestra administra las bases de datos.
  • Usuarios: no es lo mismo un empleado que un usuario con acceso. El modo desarrollador muestra opciones técnicas.
  • Módulos: Compras, Ventas, Inventario, Facturación y Sitio web. OCA reúne extensiones comunitarias. Importación CSV/XLSX con comprobación previa.

Tema 3 · Explotación y adecuación de Odoo

Modelo de datos, personalización, consultas y seguridad en PostgreSQL.

Ver apuntes
  • OpenObject: framework RAD de Odoo. El ORM mapea clases Python a tablas PostgreSQL; MVC separa modelo, vistas XML y lógica del controlador.
  • Personalizar: pueden adaptarse los procesos, el ERP o ambos. Conviene usar los mecanismos del fabricante y respetar las reglas de negocio.
  • Consultas: informes puntuales pueden leer la BD directamente; para informes periódicos se recomiendan herramientas integradas del ERP.
  • Mapeo: el modelo hr.employee corresponde habitualmente a hr_employee; work_email es el correo laboral.
  • Relaciones: category_ids representa una relación muchos a muchos a través de employee_category_rel.
  • Seguridad: otorgar solo lectura para análisis; pgAdmin ayuda a administrar roles, privilegios y ACL. CREATEROLE permite crear roles.
